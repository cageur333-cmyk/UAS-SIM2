Dokumentasi Rekayasa Perangkat Lunak

Penerapan Metode Waterfall pada Pengembangan Sistem ERP Toko Bangunan

Dokumentasi ini disusun secara terstruktur berdasarkan 5 tahap siklus hidup perangkat lunak klasik (Waterfall SDLC) sesuai standar tugas mata kuliah Analisis & Perancangan Sistem / Rekayasa Perangkat Lunak.

Fase 1: Requirements Analysis

1. Analisis Kebutuhan Sistem (Software Requirements)

Mengidentifikasi seluruh kebutuhan fungsional dan aktor yang terlibat pada proses bisnis toko bahan bangunan:

Kebutuhan Fungsional (Functional Requirements)

  • FR-01: Sistem mengelola master data produk material lengkap dengan satuan (sak, truk, batang, dus) dan safety stock alert.
  • FR-02: Sistem memproses transaksi kasir POS (tunai & tempo/kredit) yang otomatis memotong stok barang.
  • FR-03: Sistem mencatat Purchase Order (PO) pembelian supplier yang otomatis menambah stok fisik di gudang.
  • FR-04: Sistem mengelola buku kas real-time (debet/kredit) yang terhubung ke setiap transaksi penjualan dan pembelian.
  • FR-05: Sistem memantau dan mencatat pelunasan piutang pelanggan (AR) dan hutang supplier (AP).
  • FR-06: Sistem mengkalkulasi Harga Pokok Penjualan (HPP) dan menyajikan Laporan Laba Rugi resmi.

Aktor & Peran Pengguna (Actors)

  • 1. Kasir: Melayani transaksi penjualan toko, mencetak faktur/struk, menerima uang tunai/DP.
  • 2. Bagian Gudang: Memantau stok opname, menerima barang restock PO supplier, mutasi kartu stok.
  • 3. Bagian Keuangan: Mengelola arus kas, mencatat pelunasan piutang kontraktor & hutang distributor.
  • 4. Pemilik / Manajer (Owner): Memantau dashboard KPI, evaluasi profitabilitas dan laporan laba rugi.

Fase 3: Implementation

3. Implementasi Sistem (Coding & Tech Stack)

Sistem diimplementasikan menggunakan arsitektur web modern yang ringan, cepat, dan mandiri tanpa dependensi rumit:

• Backend: Node.js & Express.js dengan REST API Endpoint modular.

• Frontend: Semantic HTML5, Vanilla JavaScript (ES6+ modular state management), dan Vanilla CSS Design System kustom.

• Database Storage: Persistent JSON Storage dengan struktur relasional ACID-like atomic transactional writing.

• Interkoneksi ERP: Setiap transaksi penjualan (`POST /api/sales`) langsung memotong `products.stock`, mencatat `stock_movements`, dan memasukkan pendapatan ke `cash_transactions` serta `receivables` jika kredit.

Fase 5: Maintenance & Deployment

5. Pemeliharaan & Prosedur Deployment

Sistem dapat dijalankan secara lokal (localhost) untuk pengujian dosen, maupun di-deploy ke cloud VPS (Ubuntu/Nginx/Node.js) atau platform seperti Railway/Vercel/Render.
